## 6. Lessons learned

| Lesson | Detail |
|---|---|
| Relationship collections ≠ queries | `lecture.segments.delete()` raises `AttributeError`; use `.clear()` under delete-orphan cascade |
| Always run smoke-test clients unbuffered | `python -u`; buffered stdout masked a live failure for 15 minutes |
| Cold-start cost is real | torch import ≈ 22 s; first Whisper run downloads weights once (~140 MB) |
| New SQLAlchemy models need `init_db()` | `create_all` runs at server startup only; standalone scripts must call it themselves |
| Groq wraps JSON in code fences | Extraction responses come back as ```` ```json … ``` ```` — Phase 2 parser must strip fences |
| Retired model names fail with 404, not 401 | Auth still succeeds; check `models.list()` when a model name stops working |
| MiniLM underestimates paraphrase similarity | "GD Optimization" vs "Gradient Descent" scored 0.477 — threshold 0.85 only collapses near-exact dupes (conservative, deliberate) |
| Don't fight the flaky background server for env | Launched uvicorn didn't inherit `.env`; added explicit `load_dotenv` in `main.py` + verify with TestClient instead |
| First `SentenceTransformer` use downloads weights | ~90 MB MiniLM, adds ~1 min one-time; repeated loads cached |
| Cold `import sentence_transformers` is 35–62 s on this box | Inline `python -c` import checks can blow the 120 s tool timeout; prefer a script file + `PYTHONPATH=<repo>` for import verification |
| Lazy-import heavy ML libs at call time, not module top | `routes.py` importing `classify_prerequisites` pulled sentence_transformers+torch into API boot AND every pytest run (69 s suite). Moved ST import behind `_st()`; suite now 11 s, server boots light |
| TestClient serves the app from a different thread | `sqlite:///:memory:` is per-connection → endpoint code sees "no such table". Fix: `create_engine("sqlite://", poolclass=StaticPool, connect_args={"check_same_thread": False})` |
| Double-check `Path(__file__).resolve().parents[i]` indices (regression) | `backend/main.py:17` `load_dotenv(...parents[2]...)` resolved to the PARENT of the project root (`Desktop`), not the root (`parents[1]`) → `.env` never loaded, `groq_configured:false`; only worked because `GROQ_API_KEY` also lives at OS level. **FIXED** (`parents[2]`→`parents[1]`); health probe now reports `groq_configured:true` from `.env` |
| Groq reset-header parser matched `m` before `ms` (regression) | `_parse_reset_seconds("500ms")` returned 30000 s (500·60) because the old char-loop accepted unit `m` first. Real 429s carrying `x-ratelimit-reset-requests: 644ms` therefore raised instead of retrying in both `llm._call_groq` and Whisper. **FIXED** with `re.findall(r"([0-9.]+)\s*(ms\|s\|m\|h)")` (longest-unit-first alternation); regression tests added. Lesson: Groq sets `ms`/`s`/`m`/`h` resets per window — parse with unit precedence, and always exercise 429 handling with a genuine `httpx.Response` (groq's `RateLimitError.__init__` needs `response.request`) |
| Groq audio 500 ≠ content (2026-09-12) | A ~560 s Groq Whisper chunk 500'd reproducibly while its two halves passed — looked content-dependent, was not. Deep-dive traced it to `ffmpeg -f segment`: the SEGMENTER's **trailing FLAC chunk is malformed** (3.7 KB of content lost; Groq's parser rejects it with 500 while a cleanly re-encoded slice of the identical audio passes side-by-side). Root-cause fix: `_split_flac` now re-encodes each chunk as a fresh standalone FLAC (`-ss/-t` + `-c:a flac`) instead of `-f segment`, hard-caps chunks at 300 s (`GROQ_WHISPER_MAX_CHUNK_S`), and retries transient 500s with backoff (`LECGAP_WHISPER_500_BACKOFF`). Lesson: when an API 500 isolates to "the same audio works alone", suspect your chunk/preprocessing shape before your content — then prove it by transcribing the identical audio re-encoded two different ways |
| TestClient masks background-task races (2026-09-15) | FastAPI `BackgroundTasks` run **synchronously after each response** in TestClient, so the UI's `/concepts`→`/graph` race never reproduced in the API suite — it only bites a live uvicorn server where both workers run concurrently. Same trap as the `:memory:` per-connection gotcha above: the test harness's determinism is precisely what hides concurrency bugs. Lesson: audit worker entry points for "query-then-return" that can race a not-yet-persisted dependency, and chain by data dependency server-side rather than trusting client call order |
| Stream-copy clip cuts freeze on keyframes (2026-09-15) | `-c copy` is ACME-fast but ffmpeg can only cut on I-frames, so `-ss/-to` + copy snaps to the prior keyframe → first decoded frame is a freeze and audio starts earlier than the video. The 08-23 Phase 5 entry sold stream-copy as a feature ("instant and lossless"); it was a latent-quality bug. Re-encode default landed; judged acceptable even though 115 clips now take minutes on CPU. Lesson: "fast and lossless" is the wrong framing — lossless ≠ frame-accurate |
| Stage 2b was a patch, not a fix (2026-09-15) | Extraction stamped every concept with its whole chunk's span; `refine_timeline.py` reverse-engineered spans via substring search + stride sampling + per-concept LLM calls. That compensated for a granularity mistake upstream instead of fixing it — the same failure pattern as the `-f segment` saga: fix the *product* of the pipeline, not its shape. Lesson: when correctness work balloons into O(concepts) LLM calls, the extraction boundary itself is the root cause — change the boundary (see lecture-structure pass) |
